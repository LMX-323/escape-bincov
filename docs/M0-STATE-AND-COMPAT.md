# PR16 M0：状态、兼容与候选事务

2026-10-05，基线 `49738b89cc8556a0b39d339239bf09945e44ab9e`。实施分支 `feat/buildings-rpg-mall`，继续由 [Draft PR #16](https://github.com/xuys2025/escape-bincov/pull/16) 承接。详细顺序见 [规划 PR #17](https://github.com/xuys2025/escape-bincov/pull/17)。本文记录第一批基础实现；不表示建筑、RPG、基地或商场已可玩。

## 1. 已落地边界

- 新增无 DOM/Phaser 的地图上下文、扩展状态与校验器，覆盖角色、成长、基地、有限队列、多图快照、追击互斥和动态上限。
- 主档封套 v4 将扩展状态与档案、活动世界写入原来的同一记录；写入成功后发布。正常入口仍运行原海岸，**不会自动启用扩展状态**。`enableExpansion` 只供明确接入及 `?test=1` 验证使用。
- 两张小图夹具验证候选换层：先确认目标落点，再迁移玩家、有限轨迹结算来源弹丸、产生单次伤害/尸体/枪伤训练量、移交存活目击者、推进有限生产游标，最后一次保存。
- 候选票据不可由调用方修改。失败保留同一候选用于重试；成功后票据失效。基线修订、实时状态或其他窗口改变时拒绝旧候选。这个原型尚未接建筑场景、换层输入锁和抵达事件调度。
- 新增清洁布料定义及三配方凭据校验；尚未开放商人供应、建造、入队、取消或领取界面。现有 20 种物品、商人货单和海岸物资随机流不变。

## 2. 格式和状态所有权

| 数据 | 版本/归属 | 唯一写入者与约束 |
| --- | --- | --- |
| 主档键 | `escape-bincov.session.v2` | RecoveryStore；仍为一次 setItem，保留 Web Locks 和原字节比较 |
| 旧档案 | profile v2 | 现有领域规则；不把新增玩法字段塞进会被旧端丢弃的档案 |
| 旧主档/检查点 | session v2/v3、coast-v1/coast-v2 | 现有迁移和海岸校验器；活动世界、身份、RNG、容器不重新生成 |
| 新主档 | session v4 | 必须包含 expansion 与 systemsBackup；拒绝未知顶层字段，不能降级覆盖 |
| 扩展状态 | expansion v1 | SaveSession 候选事务；身体/成长/基地/可选多图行动同档提交 |
| 新多图快照 | LayeredRaid v1，worldVersion + layoutRevision | 数据不携带任意地图定义；只能由内置解析器识别已注册不可变布局 |
| 当前地图/冻结地图 | 每图 LayerState | 当前图普通模拟；非当前图必须没有在途弹丸，局部时间不补算 |
| 追击者 | 来源地图、事件、目标地图三选一 | 同一出生 UID 全局唯一；死亡取消事件，并在死亡图留下唯一尸体 |
| RNG/局内实体 ID | raid.rng / nextEntity | 候选内抽取与分配；库存插入可注入该分配器，不读取墙钟生成掉落 UID |
| 生产批次 | batch-N / nextBatch | 记录入队时工作台等级、付费、产物及锁定时长；校验配方、顺序、数量、唯一 ID |
| 终局原因 | death / timeout / extract / abandon | v4 保留 reason；abandon 的现有物资失败结果仍为 death，不冒充已实现死亡身体重置 |
| 扩展备份 | recovery-backup formatVersion 4 | 活动、已结算和待结算均包含完整扩展状态；v1/v2 已结算备份和旧活动备份仍可读取 |

正式居民楼与商场版本要在各布局完成时登记；当前生产解析器尚未注册新地图，`prototype-v1` 仅由规则测试显式注入。普通入口不能导入这个夹具并声称可以游玩。

## 3. 三种时钟

| 时钟 | 单位与推进边界 | M0 已验证 / 后续工作 |
| --- | --- | --- |
| 地图局部时间 | 秒；仅当前图普通模拟 | 换层不推进来源 AI、攻击或时间；离层现有弹丸一次结算后清空；M1/M2 接场景模拟 |
| 整局行动时间 | 秒；暂停/后台/故障停止 | 快照保存原 270/300/600 秒标志与换弹/冷却，换层不清零；M2 接调度、潮位改路与抵达 |
| 现实时间 | 毫秒游标，批次时长为秒 | 生产按有限批次推进、回拨取非负时间、成品最多三批；满区后的停工时间不结转；M5 接位置分段与身体恢复 |

生产时钟内核不会推进行动、追击或身体恢复。待结算扩展备份标记 `settlement`；成功结算/导入该候选后才转 `base`，以当前时间开始基地区间。M5 必须再整合等待结算期间的生产补算；当前不启动自动离线补算。

## 4. 迁移、备份与导入决策

1. v3 保持默认，启用 v4 必须成功原子写入；配额失败时没有已启用标记，旧字节可导出。
2. 第一次启用保留主档当时原始字节到 systemsBackup；后续 v4 保存不递归嵌套上一份 v4。原 legacyBackup、migrationBackup 继续保留。原始档案字段和活动海岸快照不补奖励、不重投物资。
3. 新次要状态初始化100，永久属性10、进度0、声望空表默认0、幸运1；旧活动生命/耐力/污染/流血/疲惫初始化自原快照。旧活动局继续用原海岸规则，直到原规则结算；新增系统不在中途生效。
4. v4 以后禁止以 profile-only 备份或 v3 主档降级覆盖，避免抹掉身体、成长和队列。UI 继续先验证并确认覆盖；v4 导出始终用完整封套。
5. 导入是**完整替换**，不将新库存/成品与历史队列拼接。同一备份导入不额外发历史奖励；批次和游标一起替换。M5-F 仍需验证领取/出售/新生产等完整历史反例；不能宣称目前已通过生产收益重复导入专项，更不能承诺抵抗任意手改 JSON、删档或跨设备搬运。
6. 待结算 profile、扩展身体/成长/队列及终局原因一起保存候选和导出。写入失败时活状态和候选仍分离，未保存结果不显示为完成。
7. 验证使用 main 的真实单文件 HTML，SHA-256 `2984e201d2b33c0f242e2c290f01425652463ef20b25df47b528471b4be5e731`；不手写旧客户端模拟拒读。
