## 布局二版（`mall-v2` / `mall-layout-2`）

![布局二版切片平面示意](layout-v2-slice.png)

按世界数据绘制的平面示意，不是游戏画面。

### 规则

- 数据在 [`src/mall-layout-v2.ts`](../../src/mall-layout-v2.ts)，由 [`src/mall-world.ts`](../../src/mall-world.ts) 的 `mallWorldV2()` 在首次调用时生成。一版 `MALL_WORLD` 的生成步骤只拆成共用函数，输出逐字节不变（测试比对 SHA-256）。
- 家具逐格登记为装饰：B 物化为 `wall`（挡人、视线、子弹），M 为 `low`（只挡人），V 不改格。装饰名就是家具类型；多格件写 `类型#dx,dy`；货架、冷柜、样板隔板是东西向连排件，由视图按左右邻居选端头和中段。
- 二版只改第 1 节列出的八个区域和超市北侧临街一排（x 30–44，y 19）；其余区域保留一版的角标装饰，二层食品与非食品卖场保留一版短货架。
- 两版均注册到 `resolveExpansionWorld`，存档按原世界与修订恢复；`beginRun(..., { mallLayout: 2 })` / `deploy({ ..., mallLayout: 2 })` 显式选择二版，未传仍是一版。`initializeMallRaid` 的可选 `world` 参数默认仍是一版。

## 布局三版（`mall-v3` / `mall-layout-3`，2026-10-14）

二版的碰撞不能在同一个修订号下改：已存的二版行动里，人或敌人可能正站在要改的格子上，读档时会因为“站进了家具”被拒绝，整个存档会锁住。所以茶几和露台桌椅的碰撞放到三版里改，二版原样保留。

- 数据：`MALL_V3_LAYOUT`（[`src/mall-layout-v2.ts`](../../src/mall-layout-v2.ts)）由二版按一张替换表逐项换出来，一层和二版完全相同。二版数据一个字节都没动，测试钉住了二版世界的 SHA-256。
- 只改两处：
  - F2-13 两个客厅的茶几改成 2×1 的 `coffee-table-wide`，放在 (58,19) 和 (58,33)，紧贴沙发南边，和沙发同宽、同中心。原来是一格的茶几，隔着一整行，还偏在沙发西半边。茶几画的还是那张 30 像素宽的图，居中放在两格占地上，投影只画在图下面。
  - F2-18 露台四组桌椅改成 2×1 的 `bistro-set`，放在 (66,31)、(70,31)、(66,36)、(68,40)。椅子不再画在可以走过去的格子上。
- 出击和恢复：`?sample=mall` 的新出击用三版。之前开始的二版行动，在标签页、水产站出发和“继续行动”里都照常按二版恢复。三版记录配二版修订号（或者反过来）一律拒绝，不覆盖原始数据。不认识三版的旧包遇到三版行动也会拒绝并保留原始数据，换新包就能继续。普通入口仍是一版。
- 检查：落点、穿行带、通道宽度、两种潮位连通、敌人和物资分配这些原有约束，在三版上同样通过；三版和二版只在上面这些格子上不同。`test:mall-sample` 的 M18 在真实浏览器里验证两件事：继续一个二版行动仍是二版、茶几在旧位置；新出击是三版、茶几居中。`scripts/mall-runtime-compat.mjs` 验证 main 的包遇到三版行动会拒绝，并保留原始字节。

## 2.5D 样板（`?sample=mall`）

### 怎么打开

双击仓库根目录的 `商场试玩.html`，或打开 `start the game.html?sample=mall`。进入水产站后出击区域已选好“滨湾商场”，种子可留空。出生在正门广场西端，面朝正门。不带 `sample` 的普通入口不变：商场仍是布局一版，在原来的 Phaser 画面上跑。

画面缩放（城中村样板相同）：默认取整数倍，而且只会拉远，不会拉近，最多多看三分之一。
- 1920×1080 是 2 倍，能看到 30×17 格，和 Phaser 行动画面一样大；原来是 2.5 倍、24 格宽。
- 2560×1440 是 3 倍。
- 1280×720、1366×768 这类窗口没有合适的整数倍：1 倍要看 40 格，2 倍只剩 20 格，比敌人的射程还近。所以仍用 1.67、1.78 倍，24 格宽。
- 地址后加 `?crisp=1` 取最近的整数倍，可能拉近（1280×720 下 20 格宽）；加 `?crisp=0` 是原来的画面，任何窗口都 24 格宽。

### 入口与存档

- `?sample=mall` 时新出击用布局三版（标签页和水产站出发都一样），存档里是 `mall-v3`；继续行动按存档里的布局恢复，之前的 `mall-v2` 行动仍在 2.5D 画面上按二版继续。样板只画 `mall-v2` 和 `mall-v3`，其他行动照旧走原画面。
- `?sample=village` 的行为不变（仍预选居民楼，空种子仍挑城中村出生点）。
- 存档格式、Runtime 规则和普通入口都没有改。

### 画法

- 地面：每格按区域选 Sol 的地面图，64 像素的图按格子奇偶取四分之一，跨块拼接不错位；滩涂格仍画泥地，潮水照旧盖上去；二层楼外临空处画两层楼下的暗色街面。杂物贴花和墙、家具的投影烘进地面块。
- 墙：同一种墙（顶面、哪几边露边、立面、女儿墙栏杆）只画一张图。一层地图边是封锁围挡，二层楼外只有露台一圈画矮女儿墙，其余临空不画墙。东西向的真入口上画门头（大门用入口门头，其余用卷帘门头），顶面和墙顶对齐；南北向侧门南边那段墙压低成两级台阶，让门洞露全。
- 家具：每件一张图，按占地南边线排前后，玩家走到后面时会淡出，敌人在后面显示轮廓。货架端头立通道号牌（1 到 9 号，从北到南、从西到东），生鲜、冷藏、家居的牌子画小图标。未布置区域里没有名字的低矮碰撞格放一件替身杂物（托盘货、倒地购物车、沙袋、残堆），没有名字的孤立单格画成柱子，其余没有名字的墙格画成墙。露台咖啡桌是程序绘制的一组桌椅。图比占地窄的家具（三版的两格茶几）居中画，投影和接触暗线只画在图下面。
- 发光：冷柜、导览柱、落地灯、出口灯、应急灯、玻璃幕墙和二层窗户叠一层发光图，跟着所属家具或墙一起淡出。
- 灯光：吊顶已切掉，所以灯管只给光、不画灯具；坏灯管会闪（系统“减少动态效果”时不闪）。冷柜、落地灯、导览柱、出口灯和应急灯有自己的小光，玻璃幕墙往室内透一点天光。房间被揭示后，它的灯光在 0.3 秒内亮起来；房间一被隐藏就立刻熄灭，所以未揭示的房间任何一帧都不漏光（城中村相同）。环境光分三种：楼体内是室内，广场和露台是室外，二层临空更暗。
- 切墙：玩家所在房间的墙（连同它的南墙）剖开，进出房间各有一格缓冲；在走廊里剖开所在那段走廊正前方一两排的墙；北面和东西两侧外墙不剖；封闭的检修核（两层中间那块 9×7 的实心区，后面没有地面）任何时候都不剖。原来二层大厅把它包在里面，人走过时整块会变成条纹，现在保持实心。剖开的墙只虚化墙顶和上半截立面，挡路的那一格保持实心。挡住玩家的墙仍按原规则淡出。
- 入口：每个连接两个不同地方的门洞（两层共 21 个）在 9 格内显示城中村那种绿色门角标和双向箭头，画在墙的上层，墙挡住时也看得见；地面有一道门槛线。
- 楼梯：已画出的 S-N 楼梯不挂名字，地面画两道黄色箭头指向楼梯；其余楼梯 8 格内用 HUD 像素字显示名字，站在楼梯口时让给头顶提示。
- HUD：显示楼层和所在地点（室外地点如正门广场、东侧露台也显示），未布置的房间稍暗并标“样板外”。
- 天气与声音：雨只下在楼体以外（一层广场、二层露台），进楼后雾在半秒内散掉，室内不飘纸屑；海声在楼体内闭合，广场和露台是室外。
- 没有素材时（`&art=placeholder` 或素材解码失败）商场仍用通用占位画面，能玩。
- 镜头（城中村相同）：镜头跟着人物“取整后”的位置走，走路、跑步时人物在屏幕上稳定不动，不再相对背景来回抖一个像素。镜头跟随改用 Runtime 推进人物用的那个时钟。地面按人物自己的整像素步子滚动；帧开始时间有抖动时，偶尔会有一步走 3 像素。武器和手臂随身体一起取整，不再相对身体闪动。
- 瞄准前探（城中村相同）：平时减半为 24×17 像素，鼠标从人物一侧甩到另一侧，画面滑动从 96 降到 48 像素。按住右键的远看距离不变（81.6×57.8），所以按下或松开右键时画面会多滑一点。触屏也跟着减半。

### 顺带修的共用问题

- 房间重叠时（例如二层 F2-06 包着 F2-10），画面层原来按“第一个包含的房间”判断，外层已揭示、内层未揭示时可能漏出子弹、火花、血迹、命中标记、方向提示和受击声。现在与 Runtime 一致：所在的每个房间都揭示了才显示。
- 命中标记和受击声原来只看弹着点。弹着点在目标周围一圈上，目标贴着房间边缘时会落到房间外的走廊里，于是未揭示房间里的敌人被打中也会提示、出声。现在还要看目标本身是否可见。尸体溅出的血和血泊也跟着尸体所在的房间隐藏。这两处在本分支之前就有。
- 撤离点在 Runtime 发布它的任何楼层都列出和指引（原来只在沿海大地图）。
- 图集页改为每帧最多上传一次，避免重建或淡出时整页反复上传。

#### 第二次反馈：家具比例（F-05）

看了上面的修正后，维护者又说“沙发和桌子还是瘦，比例不对”。原因在上一轮给 Sol 的尺寸：那些数字是按格子估的，没有按真实尺寸换算。沙发的座面被抬到和靠背一样高，前面是一大片竖面，看着像个矮柜；茶几的桌面画满了整格，成了一张约 1.3 米见方的深方桌，图竖着比横着长，所以显瘦。床宽大于长，长椅的座面有桌子那么高，也是同一个毛病。

这次所有家具按同一把尺子重新核对：24 像素约 1 米（用已经认可的冷柜、货架对出来的，人物画出来 39 像素高）。维护者在对比图里选了方案，Sol 按逐行模板重画了五件家具和落地灯的发光图（素材清单第 4 版）：

- 床：宽 56、长 58，贴住南边。
- 茶几：30 宽、26 高，矮而横，放在格子正中。
- 长椅：56 宽，座面约 0.45 米高，放在格子正中。
- 落地灯：约 1.7 米高，立在格子正中；阴影只画圆底座，灯光挪到灯罩下面。

画布、锚点、碰撞和布局版本都没有变，已有的二版存档照常读取。`test:mall-sample` 的 M14 改成从贴图量出每件的底部透明行，检查阴影正好停在画出来的底边（沙发和床 0 行，茶几和长椅 8 行），落地灯的阴影只有底座大小。

#### 第三次处理：遗留的几项（维护者授权按 Opus 的判断定，2026-10-14 晚）

先对每一项分别调查、复核，再动手。

| 项目 | 决定 | 理由 |
| --- | --- | --- |
| 镜头取整 | 改（城中村一起） | 人物和镜头各自取整，走路时人物在屏幕上每秒来回抖 10–70 次。改成镜头跟着人物取整后的位置走，抖动降到 0，地面滚动的步子基本不变 |
| 瞄准前探 | 平时减半，右键不变 | 甩鼠标时画面滑动减半，瞄准点被镜头带偏的角度也减半（90 度甩向敌人时从 19 度降到 10 度）。朝瞄准方向仍能看到 408 像素，比所有敌人的视野和射程都远；要看更远就按右键 |
| 默认整数倍缩放 | 改成“只往远拉的整数倍”（城中村一起） | 非整数倍时，镜头每走一步，细节都要重新糊一遍，这是晕的直接原因之一。只往远拉，就不会让更多攻击来自画面外（10-08 定“保持 24 格宽”就是为了这个）。1280×720 没有合适的整数倍，保持原样 |
| 灯光淡入 | 改（城中村一起） | 走近超市、大堂时，10–17% 的画面在一帧内突然变亮。改成 0.3 秒亮起；隐藏仍然立刻熄灭，保证不漏光。系统“减少动态效果”时也淡入，因为亮度渐变不算动态 |
| 商场墙整体降低 | 不改 | 从 48 降到 32 像素，一个被完全遮住的格子也露不出来，墙顶的平面一点不少，却会切掉 Sol 立面上的通风带和窗户 |
| 房间天花板 | 不加 | 商场是开敞的大厅，70–80% 的室内地面在房间里；人走开几格，天花板就会盖回去，画面里会多出大片平板，认路更难。也起不到防漏的作用（敌人、物资、灯光已经按揭示隐藏） |
| 茶几离沙发远且偏西 | 布局三版里改 | 见上面“布局三版” |
| 床、长椅接触暗线两头多 2 像素 | 改 | 接触暗线只画在图的实际宽度下面 |

顺带修了一处：二层大厅 F2-01 把检修核包在里面，人走在大厅里时检修核会被当成房间墙剖开，整块变成条纹，走出大厅又变回实心。这正是 F-04 说的那种晕。现在检修核永远不剖。
