# 应用状态与存档会话

本轮以 `f4c50bdf1ae7cd6a1c1309ea77aa765169ac4b6b` 为基线，把存档流程从界面中拆出。技术栈仍是 TypeScript + Phaser，领域规则、存档格式、画面和单文件离线发布方式沿用原实现。

## 模块职责

| 模块 | 负责什么 | 不应承担什么 |
| --- | --- | --- |
| `src/domain.ts` | 物品、库存、交易、任务、迁移、结算规则；`StorageLike` 读写协议 | DOM、Phaser、音效、场景跳转 |
| `src/session.ts` | 会话数据类型、出击提交、事务回滚、结算候选与重试、导入、救济和设置保存 | 浏览器全局变量、提示文案、画面、世界掉落 |
| `src/app.ts` | 组装唯一的 `app`、`saveSession` 和音效实例；注入浏览器存储 | 玩法规则、HTML 模板 |
| `src/ui.ts` | 模板、按钮与拖放绑定、提示、下载/文件选择、场景切换；调用会话操作 | 独立实现另一套存档提交/回滚流程 |
| `src/main.ts` | Phaser 启动、窗口缩放、全局按键、页面生命周期和 storage 事件 | 交易或结算规则 |
| `src/game.ts` | 战斗场景与实时模拟；通过现有 UI 接口显示、结束行动 | 持久化事务实现 |

`session.ts` 只在运行时依赖 `domain.ts`。它不会导入 `app.ts` 或 `ui.ts`，因此可以在 Node 中创建多个独立会话，注入内存存储进行测试。`app.ts` 对 Phaser 和 RaidScene 仅使用类型导入，不会因状态模块加载而创建游戏。

`app` 是同一份会话数据加上展示状态和场景引用；没有第二份可漂移的存档镜像。`SaveSession` 持有该对象，提交或回滚时替换其中的 `save`/`loadout`。调用者应在操作后重新读取这些字段，不长期缓存容器引用。

## 提交边界

| 操作 | 提交顺序 | 失败时 |
| --- | --- | --- |
| 初始化 | `readSave`/迁移 → 中断行动恢复 → 写回 | 保留原有新档回退和 `storageOK` 提示；不能成功出击 |
| 出击 | 克隆存档 → `beginRun` 生成候选和装备 → 写入 → 发布到会话 → 启动场景 | 原存档、装备、行动次数保持不变 |
| 物品/购买/任务/医疗 | 快照存档、负载和生命状态 → 领域操作 → 安全箱检查点或救济 → 写入 | 操作拒绝、异常或写入失败均回滚参与状态 |
| 结算 | 同步弹匣 → 生成一次候选 → 锁定场景 → 写入 → 发布结果 → 切换画面 | 保留同一个 `pendingSettlement`，用于重试和备份 |
| 导入 | `decodeBackup` 校验 → 玩家确认 → 写入 → 替换会话 → 更新画面/音量 | 旧存档和待确认内容保留 |
| 音量/救济 | 修改候选 → 写入 → 替换会话 | 旧状态不变 |

`markConflict()` 将会话标记为冲突并禁止后续持久化。`main.ts` 继续负责锁定场景及告知玩家刷新/备份；待保存结算不会因此清空。这里沿用浏览器 storage 事件保护，没有引入跨窗口锁或云存档。

存档键仍是 `escape-bincov.save.v1`；备份版本、旧版迁移、死亡/超时/放弃/刷新规则、安全箱和救济弹药来源均不变。

## 添加后续功能

新增交易、任务或库存操作时，先把规则写入领域模块，再从 UI 的 `mutate` 包装器调用。它继续负责显示结果、清空选择和重绘：

```ts
mutate(() => D.buy(app.save, id, 'arms'), '物资已收入仓库。');
```

会话层的 `SessionMutation` 只接受同步 `boolean | void` 回调：`false` 表示拒绝，`true` 或 `undefined` 表示可以继续保存。异步回调不属于这一事务模型；不要在回调中发网络请求、切场景或修改未参与快照的世界对象。

| `SaveSession.mutate` 结果 | UI 处理 |
| --- | --- |
| `committed` | 展示成功，允许执行世界副作用 |
| `rejected` | 提示检查现金、空间或物资 |
| `save-failed` | 提示保存失败与操作撤回 |
| `blocked` | 冲突或待结算保护，不执行操作 |

世界掉落必须保留在成功返回之后，不能移动进事务回调：

```ts
if (mutate(() => {
    const inv = inventory(app.selectedSource);
    inv.items = inv.items.filter(entry => entry.uid !== item.uid);
})) {
    raid.drop(item);
}
```

出击、结算、导入使用专门的会话方法；不要用普通物品事务拼接这些生命周期。`persist()` 是底层写入入口，供初始化及现有显式测试接口使用，不能替代候选提交或回滚。文件解析使用 `decodeBackup`，不能仅以 TypeScript 类型断言代替运行时校验。

## 验证与后续边界

- `tests/session.test.ts`：无需浏览器或 DOM 替身的会话测试，覆盖实例隔离、存储访问被禁、旧档/中断恢复、出击提交时序、异常回滚、检查点、救济/设置及冲突重试。
- `tests/save-flow.test.ts`：保留 UI 适配层回归，验证待保存弹窗、重试、导入和医疗回滚。
- `scripts/save-browser-test.mjs`：真实按钮、文件下载/导入、失败出击及同源双窗口 storage 事件；`.test` 页面内容由浏览器路由本地提供，无外部服务器依赖。
- 既有领域、地图、双分辨率浏览器、界面和 ZIP 检查继续执行。测试入口及 CI 流程沿用现有约定。

这次只拆出高风险的存档/会话边界。场景里的输入、战斗和 HUD，以及 UI 模板/事件绑定仍可按具体需求继续拆分；当前没有引入事件总线、状态管理框架、触控实现或通用插件系统。后续主界面或移动输入改动应复用本会话接口，并从届时最新 `main` 开始。
