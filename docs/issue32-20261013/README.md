## 玩家可见变化与实际根因

1. **商店给出具体拒绝原因，过期清单可以原地刷新。** `settleCartResult` 原本已经区分 `funds`/`space`，院子 Runtime 却用默认失败文案丢掉区别，旧页签也只显示合并提示。两个入口现在显示同一明确原因。仓库改变时快照显式标识清单过期；院子拒绝继续放置，两个入口禁用结算并显示“刷新清单”；即使原清单为空也可以刷新，旧待买/待卖和确认票据由玩家明确操作丢弃。价格、购物车位置的含义、购入自动落仓、救济与交易原子性不变。另一窗口接管仍只读，不能靠刷新清单越过存档冲突。
2. **冷 PNG 绘制失败不再卡在空白入口。** 院子和沿海两套图片加载器的 `onload` 在异步事件内绘制；原来绘制抛错会逃出回调，Promise 既不成功也不失败。现在绘制异常和无法取得 2D context 均拒绝该 Promise，沿用现有回退及清除失败缓存路径。原图、素材许可和成功加载画面不变。
3. **SOL-F20-HUD-01 的旧 HUD 可以在放弃结果页回收。** `game.loop.sleep()` 并不关闭 Phaser 的全局鼠标监听。外部渲染器接管期间现暂停 Phaser InputManager，在交还控制时恢复此前启用状态；交接时用 Phaser `Pointer.reset()` 释放事件、按下/松开元素及按住状态，覆盖所有指针。院子→城中村的连续交接不提前恢复输入；失败回退和回到经典场景恢复输入。进一步实跑确认键盘管理器使用独立开关：原版院子20次按键使队列从0增至40，只有 Phaser 下一次 POST_STEP 才会清空。现在同时保存/停用/恢复键盘开关，并清理交接前事件队列；绑定 Phaser 3.90 的队列字段有结构检查与浏览器门禁。
