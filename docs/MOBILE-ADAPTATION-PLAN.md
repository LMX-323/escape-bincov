## 1. 首版要达到什么结果

手机玩家能在浏览器中完成「整备 → 出击 → 移动与交战 → 搜刮 → 整理背包 → 撤离 → 保存 → 再次进入」的完整循环。沿用暗绿海港、褪色标牌、暖色警示和像素素材，保持桌面端的操作与画面质量。

采用以下首版方案：

- **战斗横屏；菜单、整备、商店、任务和结算支持横竖屏。** 竖屏可以整理装备，进入行动前提示横置；行动中转竖屏进入暂停，恢复横屏后由玩家点击继续。
- **场景与界面分开缩放。** 场景保留 960×540、16:9 视野；按钮、文字和触控层按实际 CSS 像素排版。
- **左侧移动盘、右侧瞄准/单发操作盘，配少量情境按钮。** 先保留当前每次操作只发射一次的规则，再用真机试玩评估手感。
- **先保证普通浏览器可玩。** 全屏、锁定横屏、安装到桌面、震动反馈都不能成为开始游戏的前提。
- **保持现有存档与离线约束。** 不新增账号、运行时 CDN、远程字体或必需的联网资源。

本期交付范围是触控网页适配。原生 App、微信小游戏移植、多人联机、云存档、竖屏战斗重构、手柄和完整折叠屏体验另列后续任务；PWA 离线安装也单独评估。

## 2. 面向 2026 年的设备边界

### 2.1 选择依据

“2026 年常见手机”按**仍在使用的存量设备与当前设备共同覆盖**处理，不等同于只测试 2026 年新旗舰。这里不声称任何销量或市场份额排名。

已核对的官方规格提供了尺寸与刷新率的代表样本：iPhone 17 为 6.3 英寸、最高 120 Hz；Xiaomi 17 为 6.3 英寸、1–120 Hz；Galaxy A56 5G 为 6.7 英寸、120 Hz；HUAWEI Mate 80 为 6.75 英寸、1–120 Hz，官方列出的操作系统为 HarmonyOS 6.0。[S1–S4]

因此以 6.1–6.9 英寸的直板手机作为主要设计范围，同时保留较小视口和较弱性能的回归档。**英寸、面板分辨率、浏览器 CSS 视口是不同概念**：不拿 1206×2622 或 1280×2832 等物理像素直接设置 UI，也不从产品规格臆造浏览器的实际可用高度。

## 4. 场景与界面布局

### 4.1 缩放和视野

场景仍按 960×540 渲染，保持地图、相机视野和像素素材。手机容器按剩余空间等比容纳；优先使用 Phaser Scale Manager 的 FIT 或经过验证的等价容器算法，不能同时叠加互相冲突的 CSS transform 与引擎缩放。[S5]

触控根节点与手机 DOM UI 挂在缩放画布之外；桌面样式保留当前视觉与整数缩放。宽屏多出的两侧空间优先放操作区域，空间不足时让低透明度摇杆覆盖画面下角。中心角色、撤离读条、生命和弹药不能被操作盘挡住。首版不通过拉伸画面、裁掉场景或扩大横向视野填满手机。

统一维护画布的实际 `getBoundingClientRect()`：鼠标绝对瞄准需从 client 坐标减去画布偏移，再除以显示比例，最后经相机转换到世界坐标；触控盘方向量不直接套成鼠标屏幕点。旋转、工具栏变化、全屏退出后重新计算边界。

`100dvh` 用于跟随动态可见高度，配合基础高度回退；`visualViewport` 用于软键盘和实际可见区域变化。只在尺寸确实变化时更新，避免键盘/地址栏动画不断重建游戏。[S6–S7]

### 4.2 安全区、文字与点击尺寸

在构建模板加入 `viewport-fit=cover`，四边应用 `env(safe-area-inset-*)` 并保留至少 12 CSS px 的普通留白。安全区不是所有系统边缘手势的完整描述，操作盘还要能按真机反馈向内调整。[S8]

拟采用的设计尺寸（不是平台合规认证结论）：

- 常用按钮触达区至少 48×48 CSS px；主操作 56–64 px，相邻独立操作尽量留 8 px。
- 移动盘/瞄准盘外径 96–112 px；优先 104 px，紧凑布局可用 96 px。
- 正文 14–16 px，表单输入 16 px；次要说明至少 12 px，关键状态不能仅靠颜色表达。
- 格位整理单格 52 px，单格物品有效命中区域至少 48 px。不要把多个邻格的不可见热区相互覆盖。
- 保留暗绿底、细描边、暖灰文字和黄绿主操作色；继续使用像素图标与系统中文字体。移动按钮不堆叠高光、发光描边或浮动装饰。

## 5. 触控操作协议

### 5.1 首版默认映射

| 桌面动作 | 手机操作 | 规则与反馈 |
| --- | --- | --- |
| WASD 移动 | 左下固定中心移动盘，拖动决定方向 | 设约 16% 死区；离盘后继续捕获该指针，抬指归零 |
| Shift 冲刺 | 左盘外圈保持约 120 ms 请求冲刺，回内圈结束 | 仍受耐力、负重、精瞄和现有步行/冲刺速度约束；首次调参须真机验证 |
| 鼠标瞄准 / 左键攻击 | 右下复合操作盘：拖动瞄准，正常抬指发射一次；轻点按当前朝向发射一次 | 持续按住仅瞄准；不自动追踪敌人，不因长按重复开火；遵守原冷却、换弹和弹药检查 |
| 鼠标右键精瞄 | 右侧“精瞄”开关 | 显示开关状态；沿用移速与散布系数；遮罩/暂停时清除 |
| E 拾取 / 阅读 | 就近情境按钮“搜刮”或“阅读” | 一次点击一次动作，沿用原距离、视线和优先级 |
| E 撤离 | 进入撤离范围后情境按钮变“按住撤离” | 按住 3 秒；抬指、移动、受击、离区、遮罩或取消事件均中止进度 |
| R 换弹 / Q 治疗 | 两个明确按钮 | 显示弹药/治疗可用性；禁用状态也说明原因 |
| 1 / 2 切武器 | 主武器/匕首切换按钮 | 状态始终可见，保持原装备与弹药规则 |
| Tab / M / Esc | 背包 / 地图 / 暂停按钮 | 背包和地图仍不暂停；所有面板有可触达关闭按钮 |

**瞄准与攻击的交互是需要试玩验证的设计选择。** 右盘采用“拖动瞄准、松手单发”，目的是让两根拇指就能同时移动与定向攻击，并保留现有单发规则。指针取消、拖入明确取消区、打开面板或切后台时不发射；每个正常触摸周期最多产生一个开火请求，不缓存冷却期内的排队射击。若试玩证实这一方案影响战斗节奏，先提交操作设计修订，不能在实现时悄悄变成自动连射。

### 5.2 输入实现边界

建议新增 `src/input.ts`（统一动作快照及重置）、`src/touch-controls.ts`（DOM 控件/指针归属）、`src/viewport.ts`（显示区域与布局能力）；是否拆到这些文件由实现 PR 说明，但不要把控制器塞进交易或存档领域模块。

`InputFrame` 至少表达：移动方向、瞄准方向/世界目标、单次开火请求、精瞄状态、冲刺状态、交互按下沿、交互持续状态、换弹/治疗/切武器请求。鼠标适配器与触控适配器输出同一语义，场景只消费动作，不读取触摸控件 DOM。

Pointer Events 提供指针身份与捕获机制，可用于为左右手和按钮分别保持状态；`touch-action` 应按区域配置。[S9] 具体要求：

1. 用 `pointerId` 绑定控件，至少处理三个同时触点；第二根手指不能覆盖第一根的归属，也不能只监听 primary pointer。
2. 操作盘独占本次触摸直到释放/取消；按钮输入不透传为 Phaser 画布点击。保留鼠标键盘作为独立来源，避免兼容鼠标事件造成重复动作。
3. 战斗操作区 `touch-action: none`；菜单列表使用正常滚动；按钮按需 `manipulation`。不全页禁止缩放，也不让菜单滚动触发开火。
4. `pointerup`、`pointercancel`、`lostpointercapture`、窗口失焦、页面隐藏、旋转、场景退出、进入遮罩都清除对应输入；恢复时没有“还按着”的状态。
5. 控件按下沿只消费一次。连续状态逐帧读取，禁止用合成键盘事件和遍历 DOM 点击来驱动战斗。
6. 触控根节点不随 `render()` 重建；若必须销毁，先取消触摸、清空动作、解除监听。
7. 输入模式参考实际 `pointerType`、指针能力与明确的“触控/键鼠”设置；不能仅按屏宽或 User-Agent 判断。混合设备切换后仍能继续操作。
8. 第一轮手机提示、世界内撤离文字、交互提示、操作指南均按输入模式显示，不能残留必须按 E / Tab 的唯一操作说明。

触控偏好默认只在运行态保存；若需要持久化左右手/大小/灵敏度，单独说明存储位置、默认值和失败回退，不能借机改写游戏进度格式。

## 6. 生命周期、存档与浏览器能力

### 6.1 旋转、锁屏、来电和切 App

游戏运行期间页面隐藏或显示区域变为竖屏：先清空动作，再进入现有暂停状态，停止环境音与活动音效。返回前台/横屏后保持暂停，点击“继续行动”才恢复输入与音频。反复切换不能叠加事件监听、音轨或游戏实例。

补测 `pagehide` / `pageshow`（包括页面缓存恢复）、`visibilitychange`、全屏退出与 WebGL context lost；GPU 上下文不能恢复时停止操作并给出准确状态，不提示“重新加载可继续本局”。恢复流程优先呈现存档错误或冲突状态，不能盖掉 `pendingSettlement`。

手机上 `beforeunload` 不能保证触发，不能把关闭确认框当成存档保护方案。[S10] 浏览器杀进程/重载后继续沿用当前“行动中断按失败结算、安全箱保留”规则。**本期不承诺断点续局，也不能保证保存失败且未导出前强杀浏览器仍能保留内存结算。** 若后续要解决后者，需要独立设计可校验的持久化结算日志及幂等恢复。

### 6.2 存档和备份

- 沿用 `escape-bincov.save.v1`、写入成功后提交、失败回滚、旧存档迁移、多窗口冲突和一次结算一次发奖。
- 手机按钮调用现有 `mutate()` / 领域规则；触控格位移动不能绕过事务。验证“转移失败无丢失”“丢弃失败不生成世界掉落”。
- 导出继续生成 JSON；Safari/华为/微信的下载或文件打开流程必须真机验证。成功创建 Blob 不等于文件已保存到用户设备。
- 下载受限时提供可选择、可复制的备份文本作为可用回退，明确说明尚需自行保存；导入文本与导入文件都必须调用同一校验器和覆盖确认。可分享文件只作能力检测后的增强。
- 私密模式与清理网站数据可能删除本地存档；保留已有备份提示，不通过“探测无痕模式”来猜测可靠性。[S11]
- Pages 与未来大陆镜像是不同存档来源，不能宣称自动共享；通过 JSON 导入导出迁移。[现有大陆指南](ONLINE-CHINA.md)

### 6.3 可选能力与降级

| 能力 | 用法 | 不支持或失败时 |
| --- | --- | --- |
| WebGL / 当前渲染器 | 起局前确认已成功初始化，并在诊断记录实际渲染器 | Canvas 回退只有完成性能验收才纳入支持；否则给出准确说明 |
| 全屏 | 点击明确按钮后请求 | 保持浏览器栏可见继续玩，不循环弹请求 |
| 锁定横屏 | 全屏成功且 API 可用时尝试 | 使用横置提示，不作为出击前提之外的第二道阻塞 |
| Web Audio | 从玩家点击入口或继续行动时创建/恢复 | 静音可玩，恢复失败不阻塞存档和结算 |
| 震动 / Wake Lock | 后续可选项，需要检测和释放 | 静默退化，不影响游戏规则 |
| PWA / Service Worker | 后续独立 PR，明确 HTTPS 在线版缓存与升级策略 | 首版不依赖；`file://` 便携版不能受注册逻辑影响 |

Fullscreen 和 orientation lock 存在支持差异、用户激活等条件；不能承诺所有手机自动全屏并锁横屏。[S12–S13] 音频应在用户手势中启动或恢复。[S14]

## 7. 性能与大陆网络目标

以下为拟定验收预算，实施前先测基线，超出时记录具体原因和调整依据。

| 指标 | 目标与测量方法 |
| --- | --- |
| 标准画质 | 按 60 fps 设计；10 分钟完整行动内，活跃战斗样本中位帧间隔 ≤18.2 ms，P95 ≤25 ms；排除人工暂停但保留真实卡顿 |
| 省电档 | 明确 30 fps 上限；中位帧间隔 ≤35.7 ms，P95 ≤50 ms；不能降低敌人数或改变计时、速度、命中规则 |
| 高刷屏 | 默认仍以 60 fps 为目标；60/90/120 Hz 下相同时间的移动距离、冷却和潮汐时间一致 |
| 持续负载 | 代表性中端机连续两局、至少 20 分钟，后 5 分钟中位帧率较前 5 分钟下降不超过 20%；记录温度环境、是否充电和省电模式 |
| 操作延迟 | 自动检查动作在下一有效模拟帧被消费；真机用录像采样关键输入，目标触摸到反馈 P95 ≤100 ms；两类证据分开报告 |
| UI 更新 | 保留现有 HUD 约 10 Hz 更新，按值变化更新 DOM；摇杆移动不触发整页 `render()` |
| 包体 | 原始单 HTML 控制在 1.9 MiB 内；HTTP 传输另测压缩后字节数，不把 ZIP 大小当网络体积 |
| 可交互时间 | 可达静态源下，4 Mbps 下行 / 150 ms RTT / 无缓存实验条件，目标 5 秒内主菜单可交互；使用资源完成 + 实际按钮响应判定 |
| 断网 | 页面载入完成后断网仍可完成整局并本地保存；首版不承诺断网刷新可重新打开在线入口 |

保持固定场景渲染分辨率，首版不按手机 DPR 把 960×540 再放大 3–4 倍。优先测量雨线、全屏叠层、程序化纹理、音频节点和 DOM 更新的消耗；必要时减少装饰特效和昂贵阴影，保留当前美术辨识度。是否调整现有 `high-performance` 请求应由真机功耗/帧时间证据决定。

大陆网络验收单独进行：移动、联通、电信至少各一个真实入口，记录地区到省级、运营商、Wi-Fi/蜂窝、首次/再次加载、结果与耗时。设备适配不会解决 Pages 的网络可达性；不可达需报告为托管问题，沿用 [ONLINE-CHINA.md](ONLINE-CHINA.md) 的备用部署路线。当前不改变发布域名，不把离线 ZIP 描述为所有 iPhone 都能直接双击运行。

## 8. 拆分实施与 PR 顺序

以下人日是基于现有规模的工程估算，不是已承诺日历工期；假定一名熟悉仓库的开发者、所需真机可用，无重大浏览器阻塞。首版合计约 **10–14 个工作日**，真机借测和外部评审等待另算。

| 阶段 | 预计 | PR 范围与主要文件 | 完成条件 |
| --- | --- | --- | --- |
| M0：测量与输入原型 | 1 天 | 记录实际视口/基线帧时间，最小双触点与松手单发原型；诊断仅测试入口 | iPhone + 中端 Android + 鸿蒙浏览器能力清单；确定右手操作方案，缺机明确标记 |
| M1：视口与输入分离 | 2–3 天 | `main.ts`、`game.ts`、`style.css`、`scripts/build.mjs`，新增视口/输入模块 | 手机界面不随世界缩小；桌面 1280×720 / 1920×1080 回归；坐标与输入语义测试通过 |
| M2：触控战斗闭环 | 2–3 天 | 触控层、HUD、交互提示、暂停及操作指南 | 双拇指完成移动、瞄准、单发、治疗、换弹、切武器、搜刮和 3 秒撤离 |
| M3：整备与库存 | 2 天 | `ui.ts`、`style.css`，复用现有交易和库存规则 | 竖屏能购买、转移、使用安全箱、格位整理、交任务；扩建仓库末行可用 |
| M4：生命周期与性能 | 1–2 天 | `main.ts`、`audio.ts`、异常 UI、测量证据；仅按结果优化 | 切后台/旋转不粘键；音频可靠恢复；保存失败可重试/备份；20 分钟中端测试达标 |
| M5：真机验收与发布 | 2–3 天 | 移动回归脚本、实际截图、兼容表、README/PLAYING/手册/发布包 | A 层真机记录齐全；普通入口通过；维护者合并后 CI/Pages 成功，再改“支持手机”声明 |

依赖顺序为 M0 → M1 → M2 → M3 → M4 → M5。每个阶段从已合并的最新 main 建分支，控制单个 PR 的审阅体积；不提前把整套移动功能塞进一个巨型 PR。发现阻塞时先修对应阶段，不靠跳过桌面/存档检查推进。

## 9. 验收清单与证据

### 9.1 自动化应覆盖的风险

新增 `tests/input.test.ts`（拟建）验证指针归属、按下沿消费、死区、取消、精瞄状态、坐标变换、冷却期无射击排队。测试以行为为准，不照抄实现。

新增 `scripts/mobile-test.mjs` 与 `pnpm test:mobile`（**目前不存在，实施时新增**），覆盖第 2.3 节矩阵和以下风险：

- 两/三触点同时操作；交换触点先后顺序；一指移出控件；系统取消触摸；菜单打开后释放手指不能补射。
- 旋转、地址栏收起/展开、全屏失败/退出、软键盘输入种子后关闭，按键和准星仍对齐。
- 48 px 有效命中区、文字不截断、关键按钮位于安全可见区域；放大系统文字后仍能关闭弹窗和导出备份。
- 大仓库横向滚动不移动物品；列表滚动不误出售；位置校验失败和存储写入失败都保持原状态。
- 出击、死亡、超时、放弃、刷新中断、安全箱恢复、成功撤离、重复结算、多窗口冲突与备份导入导出。
- 错误遮罩保持最高优先级；背包与地图的世界计时继续；暂停与后台不继续计时。

浏览器自动化可以验证 DOM 触控状态、视口和 Chromium/WebKit 回归，但**桌面 Playwright WebKit 不等于 iPhone Safari，多次合成 PointerEvent 不等于真实多点触屏**。报告必须写清事件来源；真机负责多指、系统手势、下载、热衰减、音频和应用内 WebView。针对 Chromium 的多触点自动化若需专用协议，单独标记能力，不伪称跨浏览器真机覆盖。

每个涉及 UI / 输入的实现 PR 按现有矩阵执行 `pnpm test`、`pnpm package`、`pnpm test:browser`、`pnpm test:ui`，再执行届时新增的 `pnpm test:mobile`。交易/结算改动增加 `pnpm test:save-browser`，打包变化增加 `pnpm test:portable`。M2 和最终发布执行 `pnpm test:play`，并补真人自然计时整局；自动玩家不能代替触控手感验收。

### 9.2 真机发布门槛

- A 层设备每台完成至少一局约 10 分钟的真实计时行动，覆盖潮汐翻转和成功撤离；另用可控场景检查死亡/中断等分支。
- 代表性中端机完成连续两局、至少 20 分钟性能测试；记录原始帧时间与场景条件，不能只贴 FPS 截图。
- iPhone、Android、鸿蒙分别验证导出文件能再次导入；受限入口走备份文本回退并确认可恢复。
- 至少三位未参与实现的试玩者完成首局操作任务，记录帮助次数、误触和瞄准问题；同一关键动作反复失败即回到 M0 调整，不以脚本通过替代可玩性。
- 丢档、复制物品、重复奖励、失控移动/攻击、无法退出弹窗、保存错误被覆盖为发布阻塞；某浏览器不能通过时收窄支持声明。
- 文档、构建产物和发布清单与源码一致，CI 通过，PR 获维护者合并后再核对正式 Pages 普通入口。

证据建议归档到 `docs/mobile/`：注明设备/版本/SHA 的矩阵、竖屏整备与横屏 HUD 实际截图、原始性能记录、真实触控短录像、已知问题。测试存档使用人工夹具，不提交私人数据；概念图必须标注，不能冒充实现截图。

## 11. 给后续 agents 的执行约定

以 [权威仓库](https://github.com/xuys2025/escape-bincov) 的最新 main 为唯一代码基线，先读 [AGENTS.md](../AGENTS.md)、[开发手册](AGENT-HANDBOOK.md)、README、handoff 和本计划。一次只实现被分配的阶段，在独立分支提交 PR；PR 写明基线、实际验证、真机/仿真区别、截图和遗留风险，不直接推 main、不自行合并。

一句话提示词：

> 请以 https://github.com/xuys2025/escape-bincov 的最新 main 为唯一基线，先读 AGENTS.md、docs/AGENT-HANDBOOK.md 与 docs/MOBILE-ADAPTATION-PLAN.md，按计划依次完成当前被分配的移动适配阶段，保留暗绿像素风、桌面操作和存档规则，记录真实设备与仿真测试差异，在独立分支提交 PR，不直接推送或自行合并 main，最后汇报验收证据与剩余问题。
