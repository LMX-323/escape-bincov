## 1. 首版要达到什么结果

手机玩家能在浏览器中完成「整备 → 出击 → 移动与交战 → 搜刮 → 整理背包 → 撤离 → 保存 → 再次进入」的完整循环。沿用暗绿海港、褪色标牌、暖色警示和像素素材，保持桌面端的操作与画面质量。

采用以下首版方案：

- **战斗横屏；菜单、整备、商店、任务和结算支持横竖屏。** 竖屏可以整理装备，进入行动前提示横置；行动中转竖屏进入暂停，恢复横屏后由玩家点击继续。
- **场景与界面分开缩放。** 场景保留 960×540、16:9 视野；按钮、文字和触控层按实际 CSS 像素排版。
- **左侧移动盘、右侧瞄准/连续开火盘，配少量情境按钮。** 按 D1 实现，先验证开火阈值、停止与取消行为，再铺开界面。
- **先保证普通浏览器可玩。** 全屏、锁定横屏、安装到桌面、震动反馈都不能成为开始游戏的前提。
- **加入本局检查点恢复，保留既有进度和结算保护。** 按 D2 提供版本迁移，死亡、超时、主动放弃仍按原规则结算；不新增账号、运行时 CDN、远程字体或必需的联网资源。

本期交付范围是触控网页适配。原生 App、微信小游戏移植、多人联机、云存档、竖屏战斗重构、手柄和完整折叠屏体验另列后续任务；PWA 离线安装也单独评估。

## 2. 面向 2026 年的设备边界

### 2.1 选择依据

“2026 年常见手机”按**仍在使用的存量设备与当前设备共同覆盖**处理，不等同于只测试 2026 年新旗舰。这里不声称任何销量或市场份额排名。

已核对的官方规格提供了尺寸与刷新率的代表样本：iPhone 17 为 6.3 英寸、最高 120 Hz；Xiaomi 17 为 6.3 英寸、1–120 Hz；Galaxy A56 5G 为 6.7 英寸、120 Hz；HUAWEI Mate 80 为 6.75 英寸、1–120 Hz，官方列出的操作系统为 HarmonyOS 6.0。[S1–S4]

因此以 6.1–6.9 英寸的直板手机作为主要设计范围，同时保留较小视口和较弱性能的回归档。**英寸、面板分辨率、浏览器 CSS 视口是不同概念**：不拿 1206×2622 或 1280×2832 等物理像素直接设置 UI，也不从产品规格臆造浏览器的实际可用高度。

| 位置 / 现状 | 移动端影响 | 计划动作 |

| 当前 `down && !heldFire` 才触发 `shoot()` | 玩家攻击是按下沿单发；手机需要持续请求，但不能绕过武器冷却 | 按 D1 分离桌面按下沿和触控连续意图，复用同一攻击规则 |
| `src/ui.ts` 的物品依赖 HTML Drag and Drop、双击及固定格子 | 手机拖动和页面滚动冲突，仓库十列无法同时放大后完整显示 | 单击选择 + 明确操作按钮；大仓库提供列表与格位整理入口 |
| `render()` 会替换 `#ui.innerHTML` | 若摇杆挂在同一树下，重绘可打断指针捕获或遗留输入 | 稳定的触控根节点；场景/遮罩切换统一释放输入 |
| `scripts/build.mjs` 只有基本 viewport 配置；界面含固定宽弹窗 | 刘海、圆角、地址栏和软键盘可能挡住按钮 | `viewport-fit=cover`、安全区、动态视口和可滚动弹窗 |

| `activeRun` 只含 seed/runId；`initSave()` 直接失联结算；随机数状态藏在闭包 | 仅凭种子无法还原已打过的世界，可能重新生成战利品 | 完整纯数据快照、可恢复随机状态、加载先判别恢复类型 |

## 4. 场景与界面布局

### 4.1 缩放和视野

场景仍按 960×540 渲染，保持地图、相机视野和像素素材。手机容器按剩余空间等比容纳；优先使用 Phaser Scale Manager 的 FIT 或经过验证的等价容器算法，不能同时叠加互相冲突的 CSS transform 与引擎缩放。[S5]

触控根节点与手机 DOM UI 挂在缩放画布之外；桌面样式保留当前视觉与整数缩放。宽屏多出的两侧空间优先放操作区域，空间不足时让低透明度摇杆覆盖画面下角。中心角色、撤离读条、生命和弹药不能被操作盘挡住。首版不通过拉伸画面、裁掉场景或扩大横向视野填满手机。

这个方案还需要验证世界内标签：目前撤离点文字等由 Phaser 按小字号绘制，单独放大 DOM 不会改善它们。移动模式将关键撤离名、交互提示、读条转为屏幕空间标签，或提供随显示比例校正的字号；地图图例与标记也要独立保持可读。检查点/地图坐标仍用世界单位，不把 UI 放大混入碰撞和射程。

统一维护画布的实际 `getBoundingClientRect()`：鼠标绝对瞄准需从 client 坐标减去画布偏移，再除以显示比例，最后经相机转换到世界坐标；触控盘方向量不直接套成鼠标屏幕点。旋转、工具栏变化、全屏退出后重新计算边界。

`100dvh` 用于跟随动态可见高度，配合基础高度回退；`visualViewport` 用于软键盘和实际可见区域变化。只在尺寸确实变化时更新，避免键盘/地址栏动画不断重建游戏。[S6–S7]

### 4.2 安全区、文字与点击尺寸

在构建模板加入 `viewport-fit=cover`，四边应用 `env(safe-area-inset-*)` 并保留至少 12 CSS px 的普通留白。安全区不是所有系统边缘手势的完整描述，操作盘还要能按真机反馈向内调整。[S8]

拟采用的设计尺寸（不是平台合规认证结论）：

- 常用按钮触达区至少 48×48 CSS px；主操作 56–64 px，相邻独立操作尽量留 8 px。
- 移动盘/瞄准盘外径 96–112 px；优先 104 px，紧凑布局可用 96 px。
- 正文 14–16 px，表单输入 16 px；次要说明至少 12 px，关键状态不能仅靠颜色表达。
- 格位整理单格 52 px，单格物品有效命中区域至少 48 px。不要把多个邻格的不可见热区相互覆盖。
- 保留暗绿底、细描边、暖灰文字和黄绿主操作色，继续使用像素图标与系统中文字体。允许符合画风的场景动效；装饰不得遮挡信息、造成持续掉帧或让同级按钮争抢注意力，不能以适配为由把主界面简化为通用表单。

| 地图 | 自适应地图与图例；文字单独排版；需要时提供按钮式放大和复位 | 玩家与两个启用撤离点、关闭按钮 |
| 暂停 / 结算 / 存档错误 | 限定在可见区域内，正文可滚动，主要操作固定可达 | 继续、重试保存、下载备份、返回 |

缩放只改变呈现，不改变仓库 10×6/10×9、背包 6×5、安全箱 2×2 的逻辑容量。竖屏默认物品列表展示名称、数量、占格、重量；“格位整理”保留真实网格及内部横向滚动，不能重排成六列以假装适配。单击转移继续由现有规则选择可放置位置；需要手动摆放时采用“选物品 → 点移动 → 点目标格 → 校验并提交”，首次不依赖长按拖拽。

## 5. 触控操作协议

### 5.1 首版默认映射

| 桌面动作 | 手机操作 | 规则与反馈 |
| --- | --- | --- |
| WASD 移动 | 左下固定中心移动盘，拖动决定方向 | 设约 16% 死区；离盘后继续捕获该指针，抬指归零 |
| Shift 冲刺 | 左盘外圈保持约 120 ms 请求冲刺，回内圈结束 | 仍受耐力、负重、精瞄和现有步行/冲刺速度约束；首次调参须真机验证 |
| 鼠标瞄准 / 左键攻击 | 右下复合操作盘：内圈定向瞄准，越过开火阈值并保持时连续请求攻击 | 按 D1；抬指立即停止，不在松手时补射，不自动追踪敌人；遵守冷却、换弹和耗弹 |
| 鼠标右键精瞄 | 右侧“精瞄”开关 | 显示开关状态；沿用移速与散布系数；遮罩/暂停时清除 |
| E 拾取 / 阅读 | 就近情境按钮“搜刮”或“阅读” | 一次点击一次动作，沿用原距离、视线和优先级 |
| E 撤离 | 进入撤离范围后情境按钮变“按住撤离” | 按住 3 秒；抬指、移动、受击、离区、遮罩或取消事件均中止进度 |
| R 换弹 / Q 治疗 | 两个明确按钮 | 显示弹药/治疗可用性；禁用状态也说明原因 |
| 1 / 2 切武器 | 主武器/匕首切换按钮 | 状态始终可见，保持原装备与弹药规则 |
| Tab / M / Esc | 背包 / 地图 / 暂停按钮 | 背包和地图仍不暂停；所有面板有可触达关闭按钮 |

**D1 已决定按住连续开火，不再以松手单发为默认方案。** 右盘死区内不攻击，内圈只调整方向，越过开火阈值后持续表达攻击意图；M0 比较阈值与明确触觉/视觉反馈，避免刚碰到操作盘就误射。一次有效模拟步最多处理一次攻击，始终经过 `shoot()` 的冷却、装填、弹药检查；同一原则用于当前选中的武器/匕首。停止、取消、遮罩、后台、恢复时清空意图，不缓存或补发过时攻击。长卡顿恢复不能瞬间倾泻积压子弹。

桌面左键继续沿用按下沿单发，手机连续请求只改变操作方式。30/60 fps 下连续射击的平均间隔须对照武器冷却验证，不能因按帧重复请求提升射速；同时核对弹药守恒、枪声引敌、换弹期间禁射和空弹匣行为。右手阈值可在真机反馈后调整，伤害、射速和自动寻敌属于另行提出的玩法变更。

### 5.2 输入实现边界

建议新增 `src/input.ts`（统一动作快照及重置）、`src/touch-controls.ts`（DOM 控件/指针归属）、`src/viewport.ts`（显示区域与布局能力）；是否拆到这些文件由实现 PR 说明，但不要把控制器塞进交易或存档领域模块。

`InputFrame` 至少表达：移动方向、瞄准方向/世界目标、单次开火请求、持续攻击意图及其输入来源、精瞄状态、冲刺状态、交互按下沿、交互持续状态、换弹/治疗/切武器请求。场景只消费动作，不读取触摸控件 DOM；连续意图由统一攻击调度经过原武器规则处理，不能把它转成不受控的鼠标点击定时器。

Pointer Events 提供指针身份与捕获机制，可用于为左右手和按钮分别保持状态；`touch-action` 应按区域配置。[S9] 具体要求：

1. 用 `pointerId` 绑定控件，至少处理三个同时触点；第二根手指不能覆盖第一根的归属，也不能只监听 primary pointer。
2. 操作盘独占本次触摸直到释放/取消；按钮输入不透传为 Phaser 画布点击。保留鼠标键盘作为独立来源，避免兼容鼠标事件造成重复动作。
3. 战斗操作区 `touch-action: none`；菜单列表使用正常滚动；按钮按需 `manipulation`。不全页禁止缩放，也不让菜单滚动触发开火。
4. `pointerup`、`pointercancel`、`lostpointercapture`、窗口失焦、页面隐藏、旋转、场景退出、进入遮罩都清除对应输入；恢复时没有“还按着”的状态。
5. 控件按下沿只消费一次。连续状态逐帧读取，禁止用合成键盘事件和遍历 DOM 点击来驱动战斗。
6. 触控根节点不随 `render()` 重建；若必须销毁，先取消触摸、清空动作、解除监听。
7. 输入模式参考实际 `pointerType`、指针能力与明确的“触控/键鼠”设置；不能仅按屏宽或 User-Agent 判断。混合设备切换后仍能继续操作。
8. 第一轮手机提示、世界内撤离文字、交互提示、操作指南均按输入模式显示，不能残留必须按 E / Tab 的唯一操作说明。

触控偏好默认只在运行态保存；若需要持久化左右手/大小/灵敏度，单独说明存储位置、默认值和失败回退，不能借机改写游戏进度格式。

## 6. 生命周期、存档与浏览器能力

### 6.1 旋转、锁屏、来电和切 App

游戏运行期间页面隐藏或显示区域变为竖屏：先清空动作，再进入现有暂停状态，停止环境音与活动音效。返回前台/横屏后保持暂停，点击“继续行动”才恢复输入与音频。反复切换不能叠加事件监听、音轨或游戏实例。

补测 `pagehide` / `pageshow`（包括页面缓存恢复）、`visibilitychange`、全屏退出与 WebGL context lost；GPU 上下文不能恢复时停止操作，说明能否从最后成功检查点重新加载，以及尚未提交的进度可能回退，不能笼统承诺原地无损续玩。恢复流程优先呈现存档错误或冲突状态，不能盖掉 `pendingSettlement`。

手机上 `beforeunload` 不能保证触发，浏览器也可能在不执行最后回调的情况下丢弃页面。[S10、S15] 按 D2，本期加入检查点恢复：不能等到关闭页面才第一次保存，也不能承诺每次退出前都能保存最新一帧。返回仍存活的页面继续当前内存状态；重新加载则从最近成功提交的检查点恢复，并停在“继续行动”确认界面。

### 6.2 本局恢复协议（首版必需）

**玩家规则。** 手动刷新和系统回收无法普遍可靠区分，二者统一恢复最近成功检查点；新格式的恢复能力跟随行动记录，不因横竖屏或触控/键鼠切换消失。已经成功提交的死亡、超时、主动放弃和撤离结果为终态，不再恢复该行动。回退少量尚未提交的进度是 D2 明确接受的代价；这是本地单人恢复功能，不宣称防止玩家修改存档或通过回退获得信息。

加载流程先校验版本、数据和终态，再决定展示已结算结果、恢复行动、处理旧版失联行动或显示恢复错误。绝不能先无条件调用当前 `recoverInterrupted()`，否则有效检查点还没读取就已被判失败。

若采用异步存储，启动必须先完成读取/迁移再启用场景和出击；等待期间显示加载状态，不能先写一个新档再用异步结果覆盖。读取失败、库升级被旧连接阻塞和“确实没有任何已有数据”是不同结果，只有最后一种才建立新玩家进度。

| 快照类别 | 必须记录的纯数据 | 恢复约束 |
| --- | --- | --- |
| 身份与兼容性 | 格式版本、内容/地图版本、runId、递增 revision、最近提交时间、原行动配置 | 种子不是完整快照；内容版本不兼容时阻止误恢复并允许导出 |
| 玩家和携带物 | 位置、朝向、生命、耐力、污染、流血、负重相关物品、武器/匕首状态、弹匣、救济弹药来源 | 物品 UID、数量和救济标记守恒；不凭种子重新生成初始装备 |
| 行动进度 | 已用有效行动时间、潮位、预警/翻转标记、击杀数、已读便签、换弹和攻击冷却等 | 离线/后台时间不扣行动时长；恢复不把计时、弹药或事件重新初始化 |
| 动态世界 | 稳定实体 ID；敌人位置/生命/AI 状态/计时/目标；剩余地面物资；在途子弹位置/速度/剩余射程/伤害/归属 | 已死敌人和已拾取物资不能重生；子弹不能凭恢复消失或重发；路径可重建但行为计时保留 |
| 随机与瞬时状态 | 可导出的随机流状态，影响 AI 的噪声位置/剩余时间、必要的受击/疲劳状态 | 美术/音频随机与玩法随机分离；重放不能重新随机掉落或敌人配置 |
| 进度与结算 | 与该 revision 对应的完整进度、安全箱、待结算候选及已提交 runId/结果 | 相同 runId 只结算一次；不得拼接不同 revision 的物品与世界 |

不序列化 Phaser 对象、纹理、DOM、触点和音频节点。恢复后重建表现对象；所有输入为释放状态，撤离长按读条归零，必须重新按住。恢复不得再次执行 `beginRun()` 扣物资或增加行动次数。

**保存时机与提交点：**

1. 出击开始时将扣除携入物资、活动行动标记和初始快照作为同一提交；成功后才能开始模拟。
2. 原型先按约 2 秒有效行动时间生成周期快照，最终间隔由 M0 写入成本测量确认；页面隐藏/主动暂停/旋转时额外请求快照，但这些回调不是唯一保障。
3. 搜刮、丢弃、安全箱转移、装备和医疗等物品变化须连同对应世界/生命状态一起提交。写入失败不能只回滚背包却保留掉落，或只恢复世界却保留获得的物品。
4. 维护单一、有序写入队列，在帧边界捕获同一时刻的数据；旧的异步写入不能覆盖更新的快照或已结算结果。持续写失败或保存队列长期落后时暂停，提示重试/备份，不继续声称“进度已保存”。
5. 结算候选、终态标记、奖励/统计与活动快照的退休必须在同一原子提交中完成，成功后才显示完成；清理旧记录失败也不能让已结算行动再次进入恢复列表。
6. 每次恢复以新的会话所有权/递增 revision 验证写入资格，保持多窗口冲突保护。同一行动不能由两个窗口各恢复一次后分别结算。

**存储设计必须先形成可审阅的决定。** M0 比较“同一版本化记录的原子替换”与“IndexedDB 单事务同时保存进度/快照/终态”的体积、耗时、兼容性和失败路径。Web Storage 是同步接口；不能每帧序列化整个世界。IndexedDB 可用事务保护一组写入，但退出时新建的事务不保证完成。[S11、S16] 不能用 localStorage 存奖励、另用 IndexedDB 存行动却没有原子协议；也不能把多个键的顺序写入说成事务。

保留 `escape-bincov.save.v1` 中的旧数据并提供明确迁移，禁止改主机名、换键后当作新玩家或删除旧档。若评估选择新的事务存储，原键作为一次性迁移源/原始备份保留，新数据存在后不再反复从旧键导入，不维护两套互相覆盖的主存档；此结构变更须在 M2 PR 明示并同步规则文档。若继续用原键，必须证明中断写入、旧客户端覆盖和升级回退均有可执行保护，而不是仅在 JSON 中增加一个版本号。

当前 0.1.1 的旧读者遇到未知版本会返回新档，也会丢弃不认识的扩展字段；**不能承诺旧程序能读新档**。实施顺序需先补未知版本拒写/保留原始数据，再启用新写者，提供迁移前备份和兼容回退构建。既存 0.1.1 标签页不会自动学会新协议，M0 必须用旧/新两个构建并存测试证明旧客户端无法覆盖唯一的新进度；未解决前不发布新格式。源码回退不等于直接把 0.1.1 HTML 部署回去。

旧的已结算 v1 档可以迁移；旧的进行中 v1 档没有世界快照，不能伪造续局，仍按旧规则处理并解释原因。新格式损坏、未知版本、runId/revision 不匹配或检查点缺失时保留原数据，提供导出和恢复错误，不能静默重置。若有上一份完整、未被终态淘汰的有效检查点，可明确提示后恢复；不能将其与新安全箱或新奖励拼接。

断电、用户清理网站数据、私密模式关闭或所有存储写入失败仍可能使最近进度不可恢复。这是本地浏览器存储的边界，不以“永久保活”“绝不丢档”等文案掩盖。失败后只能诚实说明最后成功提交的时间及可导出的内存状态。

### 6.3 存档和备份

- 保留 v1 进度的迁移入口、写入成功后提交、失败回滚、多窗口冲突和一次结算一次发奖；存储结构按第 6.2 节评估并在 PR 明示，不把“兼容”误写成数据结构完全不变。
- 手机按钮调用现有 `mutate()` / 领域规则；触控格位移动不能绕过事务。验证“转移失败无丢失”“丢弃失败不生成世界掉落”。
- 导出继续生成 JSON；Safari/华为/微信的下载或文件打开流程必须真机验证。成功创建 Blob 不等于文件已保存到用户设备。
- 已结算备份继续兼容现有格式。当前 `encodeBackup()` / `decodeBackup()` 不接受活动行动，恢复功能必须增加独立、带版本和严格校验的“行动恢复备份”，或在同一新封装中明确区分已结算档/活动快照/待结算候选；不得直接去掉旧验证器的 activeRun 检查。导入活动快照先验证完整性及覆盖范围，再原子替换并以暂停状态恢复，不绕过终态幂等。
- 下载受限时提供可选择、可复制的备份文本作为可用回退，明确说明尚需自行保存；导入文本与导入文件都必须调用同一校验器和覆盖确认。可分享文件只作能力检测后的增强。
- 私密模式与清理网站数据可能删除本地存档；保留已有备份提示，不通过“探测无痕模式”来猜测可靠性。[S11]
- Pages 与未来大陆镜像是不同存档来源，不能宣称自动共享；通过 JSON 导入导出迁移。[现有大陆指南](ONLINE-CHINA.md)

### 6.4 可选能力与降级

| 能力 | 用法 | 不支持或失败时 |
| --- | --- | --- |
| WebGL / 当前渲染器 | 起局前确认已成功初始化，并在诊断记录实际渲染器 | Canvas 回退只有完成性能验收才纳入支持；否则给出准确说明 |
| 全屏 | 点击明确按钮后请求 | 保持浏览器栏可见继续玩，不循环弹请求 |
| 锁定横屏 | 全屏成功且 API 可用时尝试 | 使用横置提示，不作为出击前提之外的第二道阻塞 |
| Web Audio | 从玩家点击入口或继续行动时创建/恢复 | 静音可玩，恢复失败不阻塞存档和结算 |
| 震动 / Wake Lock | 后续可选项，需要检测和释放 | 静默退化，不影响游戏规则 |
| PWA / Service Worker | 后续独立 PR，明确 HTTPS 在线版缓存与升级策略 | 首版不依赖；`file://` 便携版不能受注册逻辑影响 |

Fullscreen 和 orientation lock 存在支持差异、用户激活等条件；不能承诺所有手机自动全屏并锁横屏。[S12–S13] 音频应在用户手势中启动或恢复。[S14]

## 7. 性能与大陆网络目标

**将正确性门槛与性能目标分开。** 首版必须避免输入失控、关键操作不可达、计时错误、重复物资、损坏存档或持续崩溃；目标 60 fps，不要求每台设备都达到同一帧时间百分位。M0 先记录基线和可玩性，之后才收敛优化预算。不能为了未经测量的门槛删掉有价值的美术表现或扩大重构。

| 指标 | 目标与测量方法（除正确性外均为测量/优化依据） |
| --- | --- |
| 标准画质 | 目标 60 fps；记录 10 分钟活跃行动内引擎渲染帧间隔 P50/P95、长卡顿次数及实际操作问题，注明指标不是屏幕真实呈现延迟 |
| 省电 / 低性能 | 提供约 30 fps 的可玩档；不能通过减少敌人、延长行动或降低命中规则掩盖性能问题。未达到 60 fps 但此档操作稳定可交付 |
| 高刷屏 | 不追逐 120 fps；30/60 帧渲染及 60/90/120 Hz 屏幕下核对移动、冷却和潮汐，误差与帧调度容差明示 |
| 持续负载 | 中端机连续两局、至少 20 分钟，报告前后 5 分钟变化、操作受影响情况、温度环境、充电与省电模式；不以任意下降百分比自动判失败 |
| 操作延迟 | 自动检查输入在下一有效模拟步消费；真机录像区分“触点移动 → 瞄准反馈”“进入开火阈值 → 攻击反馈”。100 ms 可作为调查提示值，M0 后确认测量精度，不把人为按住时长算成程序延迟 |
| UI 更新 | 保留现有 HUD 约 10 Hz 更新，按值变化更新 DOM；摇杆移动不触发整页 `render()` |
| 包体 | 对照当前 1,602,448 字节 HTML，记录增长来源、压缩后传输和启动时间；取消缺乏依据的 1.9 MiB 硬上限，新增大资源须给出收益与成本 |
| 可交互时间 | 可达静态源下，用 4 Mbps 下行 / 150 ms RTT / 无缓存条件比较基线与新版本，5 秒为初始优化目标；记录实际按钮响应，网络不可达不混算为渲染慢 |
| 断网 | 页面载入完成后断网仍可完成整局并本地保存；首版不承诺断网刷新可重新打开在线入口 |

保持固定场景渲染分辨率，首版不按手机 DPR 把 960×540 再放大 3–4 倍。优先测量雨线、全屏叠层、程序化纹理、音频节点和 DOM 更新的消耗；必要时减少装饰特效和昂贵阴影，保留当前美术辨识度。是否调整现有 `high-performance` 请求应由真机功耗/帧时间证据决定。

**行动计时单独验证。** 当前 `elapsed += Math.min(delta / 1000, .08)` 会舍弃长帧超出的时间；例如持续 125 ms 一帧时，每帧只计 80 ms，这是源码推导，非真机测量。实现时将有效前台行动时钟与移动/碰撞的受限模拟步长分离：暂停/后台/恢复等待不扣时，前台卡顿不能悄悄延长 10 分钟窗口；必要时用有限子步处理模拟，不能一口气补发攻击。存档保存已用有效时间，恢复重新建立时钟起点。4:30 预警、5:00 潮汐、10:00 超时须跨帧率、长帧和恢复验证，若性能不足无法安全推进则明确暂停。

大陆网络验收单独进行：移动、联通、电信至少各一个真实入口，记录地区到省级、运营商、Wi-Fi/蜂窝、首次/再次加载、结果与耗时。设备适配不会解决 Pages 的网络可达性；不可达需报告为托管问题，沿用 [ONLINE-CHINA.md](ONLINE-CHINA.md) 的备用部署路线。当前不改变发布域名，不把离线 ZIP 描述为所有 iPhone 都能直接双击运行。

## 8. 拆分实施与 PR 顺序

**初稿 10–14 个工作日估算撤回。** D2 增加了完整行动恢复，且旧客户端兼容尚未验证，不能仍按只改 UI 的规模排期。以下是单名熟悉仓库的开发者、设备可用情况下的初步范围，合计约 **13–21 个工作日**；不含设备借测和外部评审等待。M0 限时 1–2 天先给风险证据，再重新估算剩余工作，不将本表当交付日期承诺。

| 阶段 | 预计 | PR 范围与主要文件 | 完成条件 |
| --- | --- | --- | --- |
| M0：风险原型与选样 | 1–2 天 | 双指瞄准/连续开火原型、实际视口/帧时间、快照数据地图与存储方案决定 | 两类首发真机计划；明确旧客户端保护、原子提交、体积/写入耗时和右盘阈值；重估工期 |
| M1：视口、输入与生命周期基础 | 2–3 天 | `main.ts`、`game.ts`、`audio.ts`、`style.css`、构建模板，新增视口/输入模块 | 手机 UI 独立缩放；取消/后台/旋转立即清空输入并暂停；桌面回归与计时/坐标测试 |
| M2：检查点、迁移与结算 | 4–7 天 | 纯数据快照、序列化随机流、存储适配、`domain.ts` / `save-backup.ts` / `ui.ts` / 场景恢复，必要时再拆 PR | 当前局可恢复；旧档不丢；物资/子弹/计时一致；断写、多窗口、重复结算和版本回退保护通过 |
| M3：正式触控战斗闭环 | 2–3 天 | 稳定触控层、HUD、世界标签、交互与指南 | 双拇指完成移动、持续攻击、治疗、换弹、切武器、搜刮、3 秒撤离，含中途恢复 |
| M4：整备与库存 | 2–3 天 | `ui.ts`、`style.css`，通过新提交协议复用交易与库存规则 | 竖屏购买/转移/安全箱/格位整理/任务可用，扩建仓库末行可达，失败时各状态一致 |
| M5：性能收敛、真机与发布 | 2–3 天 | 按测量优化、移动测试/证据、兼容表、README/PLAYING/规则手册与发布包 | iPhone + 中端 Android 真机闭环和恢复通过；20 分钟记录；CI 与普通入口确认后宣布具体支持范围 |

依赖顺序为 M0 → M1 → M2 → M3 → M4 → M5。M0 的输入原型用于验证，不提前把未验收控件放进正式出击入口。M2 若需拆分，先完成兼容读取/拒写保护，再启用迁移与恢复；功能启用前必须整体验证原子性，不能把半套存储协议发布给玩家。

每个阶段从已合并的最新 main 建分支，一项 PR 聚焦一个可验收改动。涉及主菜单视觉迭代时，以当时已接受的画面为准，约定稳定根节点、菜单动作和触控层挂载接口，不为复用初稿布局覆盖后续已合并的主界面。生成物只由构建产生；PR 提交前更新基线，避免在压缩 HTML 中人工解决冲突。

M0 的存储原子性/旧客户端保护未收敛，或首发设备无可用验证途径时，先报告具体阻塞；不能用继续堆 UI 掩盖风险。鸿蒙、微信、更多设备与大陆备用托管按独立扩展任务推进，不伪称首发已覆盖。

## 9. 验收清单与证据

### 9.1 自动化应覆盖的风险

在 M1 建立 `tests/input.test.ts`（拟建），验证指针归属、按下沿/连续意图、死区、取消、精瞄、坐标变换、无积压补射与时钟边界。在 M2 建立快照/迁移/事务故障测试。M0 用最小原型证据，不要求尚不存在的命令通过；测试以行为为准，不照抄实现。

从 M1 开始增量建立 `scripts/mobile-test.mjs` 与 `pnpm test:mobile`（**目前不存在**），M3 前具备正式输入回归，后续随功能扩展并纳入 CI，覆盖第 2.3 节矩阵和以下风险：

- 两/三触点同时操作；交换触点先后顺序；一指移出控件；系统取消触摸；菜单打开后释放手指不能补射。
- 旋转、地址栏收起/展开、全屏失败/退出、软键盘输入种子后关闭，按键和准星仍对齐。
- 48 px 有效命中区、文字不截断、关键按钮位于安全可见区域；放大系统文字后仍能关闭弹窗和导出备份。
- 大仓库横向滚动不移动物品；列表滚动不误出售；位置校验失败和存储写入失败都保持原状态。
- 出击、死亡、超时、放弃、刷新/系统回收后的检查点恢复、安全箱、成功撤离、重复结算、多窗口冲突与备份导入导出。
- 错误遮罩保持最高优先级；背包与地图的世界计时继续；暂停与后台不继续计时。
- 长按攻击不超冷却、不生成负弹药；抬指/取消/换武器/进入面板/后台立即停止；低帧率或恢复不补发积压攻击。
- 至少在出击提交前后、搜刮/丢弃/安全箱转移中、敌人死亡掉落时、周期快照写入中、结果提交前后注入重载/中止，核对只能出现完整的前态或后态。
- 已拾物品不重生、死亡敌人不重生、在途子弹/换弹/潮汐/随机状态可恢复；完整快照与正常连续推进在可控输入下保持规则状态一致。
- 旧 v1 已结算档、无快照的旧行动、未知版本、损坏 JSON、超大备份、runId/revision 不匹配、新旧客户端并存、导入后重复恢复均有明确行为。

浏览器自动化可以验证 DOM 触控状态、视口和 Chromium/WebKit 回归，但**桌面 Playwright WebKit 不等于 iPhone Safari，多次合成 PointerEvent 不等于真实多点触屏**。报告必须写清事件来源；真机负责多指、系统手势、下载、热衰减、音频和应用内 WebView。针对 Chromium 的多触点自动化若需专用协议，单独标记能力，不伪称跨浏览器真机覆盖。

每个涉及 UI / 输入的实现 PR 按现有矩阵执行 `pnpm test`、`pnpm package`、`pnpm test:browser`、`pnpm test:ui`；`pnpm test:mobile` 建立后作为对应门槛。M2 必须运行存档专项、迁移/故障测试和便携回归；M3 与最终发布执行 `pnpm test:play`，再补真人自然计时与中途恢复整局。新增快照格式与已批准刷新规则在实现 PR 中同步 AGENTS/手册，不能删掉旧失败测试而不补新行为证据。

### 9.2 真机发布门槛

- 首发 A 层至少一台 iPhone/Safari 和一台中端 Android/明确浏览器完成约 10 分钟有效行动，覆盖潮汐翻转和成功撤离；另检查死亡、后台返回和杀进程/刷新恢复。只对实际通过的组合声明验证。
- 代表性中端机完成连续两局、至少 20 分钟性能测试；记录原始帧时间与场景条件，不能只贴 FPS 截图。
- iPhone、Android 分别验证已结算档与行动恢复备份能再次导入；鸿蒙、微信加入对应支持声明前单独补同等证据。
- 首发至少一次由维护者或非实现者完成的触控首局试玩，记录误触、持续攻击停止和恢复提示是否理解；三位试玩者作为扩展验证目标，不以招募人数无期限阻塞发布。重复关键操作失败必须修正，不以脚本通过代替可玩性。
- 丢档、复制物品、重复奖励、失控移动/攻击、无法退出弹窗、保存错误被覆盖为发布阻塞；某浏览器不能通过时收窄支持声明。
- 文档、构建产物和发布清单与源码一致，CI 通过，PR 获维护者合并后再核对正式 Pages 普通入口。

证据建议归档到 `docs/mobile/`：注明设备/版本/SHA 的矩阵、竖屏整备与横屏 HUD 实际截图、原始性能记录、真实触控短录像、已知问题。测试存档使用人工夹具，不提交私人数据；概念图必须标注，不能冒充实现截图。
